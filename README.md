# 壁画修复底图拼接台

把同机位、同尺寸的 8 位灰度 PNG（3–8 张，边长 ≤ 512）拼成一张修复底图：
圈定共用校准区、为每张照片标注一个脚手架遮挡框，系统按灰度差中位数
约束各照片的曝光偏移，再逐像素取中位数合成；有效供值少于两张的位置
标记为“待补拍”。

技术栈：Flask + Pillow + NumPy，前端为原生 HTML/JS（无构建步骤），
Docker Compose 一键启动。

## 启动

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

数据保存在命名卷 `mural-data` 中；容器内单 gunicorn worker + 4 线程，
任务级锁保证标注/合成的并发安全。

### 本地直接运行

```bash
pip install -r requirements.txt
python run.py            # http://localhost:8000
```

## 网页操作

1. 点击 **上传 3–8 张灰度 PNG**，或点击 **载入内置示例照片**
   （5 张 256×256 合成照片，已预置校准区与遮挡框）。
2. 选择绘制模式：
   * **圈校准区**：在任意一张照片上拖动，画出所有照片共用的校准矩形；
   * **画遮挡框**：切到对应照片标签后拖动，每张图至多保留一个遮挡框，
     重画即替换，工具栏可清除当前图遮挡框或校准区。
3. 点击 **应用标注并合成**。侧栏显示每张图相对首图的曝光偏移、
   可用/停用状态、每条约束使用的校准像素数，以及合成底图。
4. 勾选 **红色标出待补拍区** 可叠加查看缺拍位置；可下载底图 PNG。
5. 修改遮挡框后再次应用：若各图偏移与可用性未变，只重算遮挡状态
   发生变化的像素（侧栏消息会显示“增量重算”）。

## 算法与规则约定

| 主题 | 约定 |
| --- | --- |
| 输入 | PNG、模式 `L`（8 位灰度）、3–8 张、全部同尺寸、边长 1–512 |
| 校准像素 | 校准区内，两图同位置均未遮挡、灰度均不为 0/255（未饱和）的像素 |
| 成约束条件 | 共用合格像素 **≥ 16** 个 |
| 两两偏移 | 合格像素灰度差 `(图b − 图a)` 的中位数 |
| 偏移传播 | 以首图（偏移 0）为基准 BFS，可经中间图传递 |
| 连不通首图 | 偏移置空、标记“停用”，不参与合成 |
| 矛盾判定 | 同一图片由不同约束路径推出的偏移相差 **> 2 灰度** 即判冲突；接口返回 409，**保留上次标注与底图不变** |
| 逐像素合成 | 仅取未遮挡、且校正后落在 0–255（含边界）的灰度，取中位数后四舍五入 |
| 待补拍 | 某像素有效供值 **少于 2 张** 时标记，叠加图中显示红色 |
| 增量重算 | 新标注无冲突且各图偏移/可用性与上次完全一致时，仅重算遮挡状态变化的像素并合并；否则全量重算 |

### API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/jobs` | 创建任务 |
| POST | `/api/jobs/<id>/images` | 上传 3–8 张 PNG（multipart 字段 `images`） |
| POST | `/api/jobs/<id>/samples` | 载入内置示例照片与预置标注 |
| GET | `/api/jobs/<id>/state` | 当前任务状态 |
| POST | `/api/jobs/<id>/annotation` | 提交 `{calib, boxes}`（或单图 `box`），触发校准+合成；冲突返回 409 |
| POST | `/api/jobs/<id>/recompute` | 强制全量重算 |
| GET | `/api/jobs/<id>/images/<i>` | 原图 |
| GET | `/api/jobs/<id>/composite.png` | 合成底图（灰度 PNG） |
| GET | `/api/jobs/<id>/composite-overlay.png` | 待补拍区红色叠加图（RGB PNG） |

## 目录结构

```
app/
  core.py              # 纯算法：校验、约束边、BFS 传播、冲突、中位数合成、增量
  server.py            # Flask 路由、任务存储、冲突回滚、增量合并
  static/              # 前端页面（index.html / app.js / style.css）
scripts/generate_samples.py   # 重新生成示例照片（确定性随机种子）
samples/               # 内置 5 张示例 PNG + annotation.json
tests/                 # pytest：13 个算法用例 + 8 个接口用例
Dockerfile / docker-compose.yml
run.py                 # 本地开发入口
```

pip install -r requirements.txt

### 自测结果（本仓库当前版本）

* `pytest`：**23 项全部通过**（13 项 `test_core.py` 算法用例 +
  10 项 `test_server.py` 接口用例）。
* 真实服务冒烟（`python run.py` + curl）：
  * 示例集 5 张图全部连通基准，恢复偏移 `[0, -14, +22, -7, +11]`，
    与生成脚本设定值一致；
  * 中心遮挡块 54×80 = **4320 像素**正确标记为待补拍，叠加图红色区域一致；
  * 仅改遮挡框再应用 → 返回 `mode=incremental`，且增量底图与独立全量
    重算结果 **逐像素相等**；
  * monkeypatch 制造矛盾约束 → HTTP 409、`conflict=true`，旧遮挡框、
    偏移表与旧底图 PNG 均保持不变；
  * 清除校准区 → 仅基准图可用，其余 4 张停用并提示；
  * 上传校验：非 PNG/非灰度、尺寸不一致、边长 >512、数量 1 或 9
    均返回 400 与中文错误信息；3 张合法图片通过。

## 已知限制 / 剩余事项

1. 任务保存在进程内存中（图片另落盘到 `data/`），服务重启后历史任务
   不可继续；当前为单 worker 部署，多 worker 需换共享存储。
2. 未做用户鉴权与任务配额，适合内网/单机协作场景；公网部署需前置认证。
3. 冲突阈值固定为 2 灰度、供值下限固定为 2 张、饱和判定固定为 0/255，
   暂未在界面上开放配置。
4. 前端未做画布触摸手势的精细适配（指针事件可用，但小屏体验未专门优化）。
5. 未提供历史标注版本管理；冲突时仅保留“最近一次有效标注”。
